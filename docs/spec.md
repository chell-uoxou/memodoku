# Meowdoku メモツール 仕様書

2026-09-19 · @rui

## 1. 概要

Meowdoku（ネコのクイーンズ系パズル）を解くときの思考メモ専用ツール。ゲーム内では置けない量のバツを自由に置いて、仮定を試すために使う。

- スクリーンショットをアップロードすると盤面（色領域・サイズ・レベル名）を読み取り、**まっさらな状態**のメモ盤面を作る
- 同時に、スクショに写っている**既存の猫とバツもインポート**し、表示ON/OFFを切り替えられる
- 1つの盤面に対して**複数のメモ盤面**を持ち、下部スクラバーで切り替える
- ブラウザ内で完結（サーバー・DB・アカウントなし）
- URLに全状態を埋めて共有できる

### 非目標

- ソルバー（自動で答えを出す機能）は作らない
- ログイン・同期・サーバー保存はしない
- 説明文・オンボーディング・ツールチップの類は原則置かない（UIは無言で成立させる）

## 2. 技術構成

| 項目 | 選定 |
| --- | --- |
| ビルド | Vite + React + TypeScript |
| スタイル | CSS Custom Properties + CSS Modules（Tailwindは使わない） |
| 盤面描画 | DOM（div グリッド）。サムネイルとOGP用途のみ SVG |
| 画像解析 | Canvas 2D + 自前アルゴリズム（OpenCV.js は使わない） |
| 文字認識 | tesseract.js を**遅延ロード**（インポート時のみ、数字と `/` に限定）。失敗時は手入力 |
| 保存 | IndexedDB（`idb` ラッパ可）。localStorage は設定値のみ |
| 圧縮 | `CompressionStream('deflate-raw')` があれば使用、無ければ非圧縮 |
| 配信 | 静的ホスティング（GitHub Pages / Cloudflare Pages 等） |

### 非機能要件

- **バックエンド・外部APIへの通信ゼロ**。画像は一切アップロードせず、`URL.createObjectURL` → Canvas で処理して破棄する
- 対応: iOS Safari 16.4+ / Chrome for Android / デスクトップ Chrome・Safari。主ターゲットはスマホ縦画面
- 解析は 100ms オーダーで完了させる（1600px に縮小してから処理）。重い場合のみ Web Worker に逃がす
- オフラインで動く（PWA / Service Worker でアプリシェルをキャッシュ）
- 画像解析ロジックは `src/vision/` に UI 非依存で切り出し、Node 上のユニットテストでスクショ固定画像に対する期待盤面を検証できるようにする

## 3. 盤面モデルとルール

N×N の正方グリッド。N は 5〜12 程度を想定し、**固定しない**（スクショ1枚目は 10×10、2枚目は 7×7）。

セルはそれぞれ N 色の領域のいずれかに属する。ルールは3つ:

1. 1色につき猫は1匹
2. 各行・各列に猫は1匹ずつ
3. 猫同士は隣接不可（斜めを含む8近傍）

このルールは**読み取り結果の検証にのみ**使う。ツール側で解を出したり、正誤判定はしない。

### 検証に使える不変条件

- 領域数 = N（上部のネコ型チップの数と一致する）
- 各領域は少なくとも1セルを持ち、**4近傍で連結**している
- セル総数 = N²
- インポートした猫の数 ≤ N、猫同士が8近傍で隣接していない、同じ行・列・色に2匹いない

これらを満たさない解析結果は「要確認」として補正UIに回す（§6）。

## 4. データモデル

```ts
type Mark = 0 | 1 | 2;            // 0=空 1=バツ 2=猫
type Marks = Mark[];              // 長さ N*N、row-major

type Board = {
  id: string;                     // regions を正規化したハッシュ（後述）
  n: number;
  regions: number[];              // 長さ N*N、値は 0..N-1
  palette: string[];              // 領域色 hex、index は regions の値と対応
  label: string;                  // "Level 62" / "Daily 9/19" / 手入力
  kind: 'regular' | 'daily' | 'unknown';
};

type Memo = {
  id: string;
  showImported: boolean;          // 既定 false
  user: Marks;                    // 書き込みは常にこの1枚（§8）
};

type MemoSet = {
  id: string;
  boardId: string;
  name: string;                   // 既定は保存日 "2026/09/19"
  imported: Marks;                // スクショから読んだ猫とバツ（セット共通・不変）
  memos: Memo[];
  activeIndex: number;
  createdAt: number;
  updatedAt: number;
};
```

### 補足

- **`imported` は Board ではなく MemoSet に持つ。** 同じレベルでも進行度の違うスクショから何度でもセットを作れるため。Board は「レベルの盤面形状そのもの」だけを表す
- **Board.id** は `regions` を row-major に走査して初出順で 0,1,2… に振り直した配列の SHA-256 先頭16文字。同じレベルのスクショは、色の並び順や名前が違っても必ず同じ Board に紐づく
- 表示ON/OFFは**描画とロックだけ**を変える。書き込みは常に `user` 1枚で、切り替えでコピーもマージもしない（§8）
- Undo/Redo はメモ単位のコマンド履歴をメモリに保持（永続化しない）。深さ100

## 5. スクリーンショット読み取り

入力はファイル選択・ドラッグ&ドロップ・**クリップボード貼り付け**の3経路。端末・解像度・ダークモード・通知バナーの有無に依存しない実装にする。

### 5.1 グリッドの位置とサイズの自動判定

1. 長辺 1600px に縮小して Canvas に描画、RGB → CIELAB に変換
2. 「彩度のあるセル色」マスクを作る: HSV の S > 0.18 かつ V > 0.25。背景のクリーム色・白カード・黒文字は落ちる
3. マスクの連結成分を取り、**アスペクト比 0.9〜1.1 かつ画像幅の 60% 以上**の最大成分を盤面候補とする
   - 上部のカラーチップ列（横長）、ルール説明カードの小さい茶色マス（小さい）、下部の緑/黄ボタン（小さい）、広告バナー（横長）はこの条件で落ちる
   - 候補が複数残ったら、次の投影解析で周期性が最もきれいに出るものを採用
4. 候補BBox内で行方向・列方向の投影プロファイルを取り、セル間ギャップ（低彩度の細い帯）の位置から**ピッチ**を求める。自己相関でピッチを推定してからギャップ位置を確定させると、スクショ1のようにギャップがほぼ無い盤面でも動く
5. `N = round(BBox幅 / ピッチ)`

### 5.2 N のクロスチェック

盤面上部の白いピル内に並ぶ**ネコ型チップの数 = N**。これは強い制約なので必ず併用する。

- チップ列の検出: 盤面BBoxより上にある、横長（アスペクト > 2.5）の白い角丸領域の中の、等間隔に並ぶ彩度のあるシルエット
- チップ数と 5.1 の N が食い違ったら**チップ数を優先**し、ピッチを N で割り直す
- チップの色 = 領域パレットの正解値。セル色のクラスタリング結果はこのパレットに最近傍マッチさせる
- **チップがネコの顔になっているものは、その色に既に猫が置かれていることを意味する**。猫の色割り当て（5.4）の検証に使う

### 5.3 セルごとの領域色の判定

セル矩形の**内側 70% から、さらに中央 40% を除いたドーナツ状の領域**をサンプリングする。中央を避けるのは、バツのストロークと猫の顔が中央に来るため。

- サンプル画素から「ほぼ白（L>88, C<8）」「ほぼ黒（L<25）」を除外し、残りの最頻色を採用
- 最頻色をパレット（チップ色）に CIEDE2000 で最近傍マッチ。ΔE > 12 なら**不明セル**としてマークする

### 5.4 猫・バツの判定（表情変化に強い方法）

色や画像テンプレートでの一致は取らない。**構造**で判定する。

| 判定 | 条件 |
| --- | --- |
| 猫 | セル内側に「ほぼ黒（L<25）」画素が 2% 以上ある。かつセル内の色クラスタ数が3以上（背景＋黒＋白＋ピンクの鼻） |
| バツ | ほぼ黒がほぼ無く、「ほぼ白」画素が 3〜18% で、その白画素が**2本の対角ストローク**を成す |
| 空 | 上記いずれでもない |

対角ストロークの確認は、セル内側を 16×16 にダウンサンプルした白マスクと、同サイズの X 字テンプレートとの相関係数（> 0.6）で行う。太さ・アンチエイリアス・セルサイズに依存しない。

**猫セルの背景色は領域色ではない**（スクショ1では猫のセルがオレンジや金色のハイライトになっている）。したがって:

- 猫と判定したセルは**領域が不明**として扱う
- 不明セルの領域は次の順で解決する
  1. パレットのうちどの色にも割り当てられていない色が1つだけ残り、不明セルも1つなら、それを割り当て
  2. 4近傍の既知領域のうち、その領域に加えても全領域の連結性が保たれる候補が1つだけならそれを採用
  3. 「チップが猫の顔になっている色」の集合と、割り当て済みの猫の色の集合を照合して残りを埋める
  4. それでも決まらなければ**不明のまま補正UIへ**（§6）。推測で埋めない

### 5.5 レベル名の読み取り

画面上部「レベル」ラベルの直下のテキストを切り出し、tesseract.js（`tessedit_char_whitelist = 0123456789/`）に渡す。

- `^\d{1,2}/\d{1,2}$` → デイリー。`Daily M/D` に整形（例: `09/19` → `Daily 9/19`）
- `^\d{1,3}$` → レギュラー。`Level N` に整形（例: `62` → `Level 62`）
- **通知バナーやDynamic Islandでヘッダが隠れることがある**（スクショ2がまさにそれ）。OCR が上記どちらにもマッチしない・信頼度が低い場合は名前を空にして、保存ダイアログの入力欄をフォーカスするだけにする。誤った名前を自動で入れない
- 「スコア」側は読まない

### 5.6 解析の返り値

```ts
type ParseResult = {
  ok: boolean;
  n: number;
  regions: (number | null)[];   // null = 不明
  palette: string[];
  imported: Marks;
  label: string | null;
  kind: 'regular' | 'daily' | 'unknown';
  warnings: string[];           // 検証に引っかかった項目
};
```

## 6. 読み取り確認と手動補正

解析後、必ず確認画面を挟む。ここで盤面を編集できることが、解析精度に対する最後の保険になる。

- 解析した盤面を実寸で表示。不明セルは斜線ハッチで示す
- 下部にパレットのチップ列。チップを選んでセルをタップ/ドラッグすると領域を塗り替えられる
- インポートされた猫・バツは薄く重ねて表示。セルを長押しで「空 / バツ / 猫」を切り替え
- ルール検証（§3）に引っかかった箇所だけ、セルの縁を細く強調する。文章での説明は出さない
- N が誤検出された場合に備え、`N −` `N +` のステッパーを置く。N を変えると領域は全リセットされ、手塗りになる
- 上部にレベル名の入力欄（解析結果をプリフィル、未検出なら空）

確認画面の完了ボタンで、Board と MemoSet（メモ1枚）が生成されメイン画面へ遷移する。この時点ではまだ**保存されていない**（§10）。

## 7. 盤面の操作

### 7.1 入力ルール

Pointer Events で統一（`pointerdown` / `pointermove` / `pointerup`、`setPointerCapture`）。touch/mouse で分岐しない。

| 操作 | 結果 |
| --- | --- |
| タップ（空セル） | バツを置く（**即座に**、遅延なし） |
| 直前にバツを置いたセルを 300ms 以内に再タップ | そのバツを猫に変える |
| タップ（猫セル） | 空に戻す |
| ドラッグ | 最初に触れたセルの状態で塗りモードが決まる。空から始めたらバツを塗る、バツから始めたら消す。猫のセルは**飛ばす**（上書きしない） |

**ダブルタップを 300ms 待ってから判定する実装にはしない。** 待つとバツ1つ置くたびに引っかかる。1タップ目でバツを確定させ、2タップ目で猫に昇格させる。結果として「ダブルタップで猫」という体感は保たれる。

- ドラッグ中のセル判定は `document.elementFromPoint` ではなく、盤面のBBoxとピッチからの座標計算で行う（速い・確実）
- 同一ドラッグ内で同じセルを2回処理しない
- ドラッグ1回、タップ1回がそれぞれ Undo の1単位

### 7.2 ブラウザジェスチャの抑止

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover">
```

iOS Safari は `user-scalable=no` を無視するので、以下を必ず併用する。

```css
html, body { overscroll-behavior: none; }
.board { touch-action: none; user-select: none; -webkit-user-select: none;
         -webkit-touch-callout: none; -webkit-tap-highlight-color: transparent; }
.board img, .board svg { pointer-events: none; }
```

```js
// ピンチ・ダブルタップズーム
['gesturestart','gesturechange','gestureend'].forEach(t =>
  document.addEventListener(t, e => e.preventDefault(), { passive: false }));
document.addEventListener('dblclick', e => e.preventDefault(), { passive: false });
// 長押しメニュー・要素ドラッグ
document.addEventListener('contextmenu', e => e.preventDefault());
document.addEventListener('dragstart', e => e.preventDefault());
// ページ全体のバウンス
document.body.style.position = 'fixed';
document.body.style.overflow = 'hidden';
```

- 盤面には `touch-action: none`、下部スクラバーには `touch-action: pan-x` を指定して役割を分ける
- すべての `<img>` に `draggable="false"`
- 高さは `100dvh` を使い、`safe-area-inset-bottom` を下部スクラバーのパディングに足す

### 7.3 Undo / Redo

盤面の上、右上に Undo / Redo の小さい丸ボタン。メモ単位で履歴を持ち、メモを切り替えると履歴も切り替わる。永続化はしない。

### 7.4 設定パネル

右上の歯車から開く小さなシート。トグルだけを並べ、**全て既定OFF**。設定は localStorage に保存し、全メモ・全盤面に共通で効く。

| トグル | 内容 |
| --- | --- |
| 自動除外 | 猫を置いたとき、同じ行・列・色・8近傍を自動でバツで埋める。自動で置いた分は Undo 1回でまとめて消える |
| ルール違反の表示 | 猫が行・列・色で重複、または8近傍で隣接したとき、該当セルの縁を細く赤くする。文章は出さない |
| 行・列ハイライト | セルを長押ししている間だけ、その行と列を薄く光らせる |
| 領域の境界線 | 領域の境目に細い白線を引く。近い色が隣り合うときの可読性が上がる |

既定を全部OFFにしているのは、素の状態ではあくまでメモ帳として振る舞わせるため。

## 8. インポートレイヤーの表示切り替え

メモごとに `showImported` を持つ。盤面の右上にある目のアイコン（OFFのときは斜線入り）で切り替える。切り替えは120msのフェードにして、どのマークが消えたのかが見えるようにする。猫のアイコンは「猫を置く」操作と紛らわしいので使わない。

### 8.1 レイヤーは1枚だけ

ユーザーの書き込みは常に `user`（N²セル）1枚に入る。`imported` は MemoSet 側の固定データで、ユーザーが書き換えることはない。表示ON/OFFが変えるのは**描画とロックだけ**で、`user` の中身には一切触らない（コピーもマージもしない）。

### 8.2 表示OFF（既定）

- `imported` は描画されない。したがって盤面からインポートされたマークは消える
- 盤面 = `user` そのもの。全セルが編集可能
- 新規メモの初期状態はこちら。インポートを持つセットでも、まっさらな盤面から書き始められる

### 8.3 表示ON

- `imported` が入っているセルは、そのマークを\*\*不透明度45%\*\*で描き、編集不可にする
- それ以外のセルは `user` を通常の不透明度で描き、編集できる
- `user` に書き込みがあるセルを `imported` が覆う場合、見た目は `imported` が優先されるが、`user` の値は保持される
- 実効表示 = `imported[i] || user[i]`

### 8.4 往復

ONで書いた内容はOFFにしてもそのまま残る（同じ `user` なので）。OFFで `imported` のセルに書いた内容は、ONにすると `imported` に隠れるだけで消えず、OFFに戻せば続きから編集できる。

### 8.5 メモを新規追加したとき

`showImported = false`、`user` は空。`imported` は MemoSet 共通なので、ONにすればどのメモでも同じものが見える。

## 9. 下部スクラバー

iOS 写真アプリの詳細画面下部のフィルムストリップを踏襲する。写真のサムネイルの代わりに**通し番号**を並べ、末尾に追加ボタンを置く。

### 9.1 見た目

- 高さ 56px 前後の横スクロール帯。各アイテムは正方形（40×40）、間隔 6px
- 中央のアイテムだけが拡大（1.25倍）して濃く、両脇にいくほど小さく薄くなる。中央位置には固定の枠線を描く
- アイテムの中身は数字（1, 2, 3…）
- 最終フレームは `+` ボタン
- `user` が空でないメモは、数字の右下に小さな点を付ける

### 9.2 挙動

- 横スクロール＋ `scroll-snap-type: x mandatory`、各アイテム `scroll-snap-align: center`
- コンテナの左右に `calc(50% - 20px)` のパディングを入れ、最初と最後のアイテムも中央に来られるようにする
- **中央に来たアイテムが選択中のメモ**。スクロール中、中央判定が変わった瞬間に上部の盤面を**アニメーションなしで**差し替える（`scroll` イベントで座標から算出、`IntersectionObserver` は遅延が出るので使わない）
- 慣性スクロール中も盤面は追随して切り替わる。iOS 写真アプリと同じく、指を離す前から中身が変わる
- 切り替わりのたびに軽いハプティック（`navigator.vibrate(5)`、非対応環境では無視）
- アイテムのタップでそこへスムーススクロール
- `touch-action: pan-x`、`overscroll-behavior-x: contain`

### 9.3 追加ボタン

- `+` フレームには `scroll-snap-align: none` を指定し、**スクラブでは選択されない**。末尾までオーバースクロールしたときに見え、タップで初めて新規メモが作られる
- 追加された新規メモは末尾に入り、そこへスムーススクロールして選択状態になる

### 9.4 メモの削除・複製

- スクラバーのアイテムを長押しで小さいメニュー（複製 / 削除）
- 削除はメモが2枚以上あるときだけ有効。確認は出さず、Undo で戻せる

## 10. 保存と一覧

### 10.1 保存

保存ボタン → シートが上がり、入力は2つだけ。

| 入力 | プリフィル |
| --- | --- |
| 盤面名 | 解析したレベル名（`Level 62` / `Daily 9/19`）。未検出なら空でフォーカス |
| メモセット名 | 今日の日付（`2026/09/19`） |

- 同じ `Board.id` が既に保存済みなら、盤面名の欄は**保存済みの名前**をプリフィルし、入力欄の下に既存であることを示す小さな印だけ出す（説明文は出さない）。保存すると既存 Board に紐づく
- 一度保存した MemoSet はオートセーブ（変更から500msデバウンス）。以降は保存ボタンを出さない
- IndexedDB のストアは `boards` と `memoSets` の2つ。`memoSets` に `boardId` と `createdAt` のインデックスを張る

### 10.2 一覧

- MemoSet を**登録日の新しい順**に並べる
- 右上のトグルで**リスト表示 / サムネイル表示**を切り替える（設定は localStorage に残す）
  - リスト: 盤面名 / メモセット名 / 日付 / メモ枚数を1行で
  - サムネイル: 盤面を SVG で描いた正方形グリッド。領域色＋1枚目のメモの猫とバツを簡略描画（猫は塗りつぶしの丸、バツは細い線）
- もう一段のトグルで**盤面グループ表示**に切り替えられる
  - 1階層目に Board をフォルダのように並べる（盤面名＋サムネイル＋紐づく MemoSet 数）
  - タップするとその Board に紐づく MemoSet が同じ表示形式で並ぶ
- 各項目は長押しで 名前変更 / 複製 / 削除 / 共有リンクをコピー

### 10.3 容量

画像は一切保存しない。1 MemoSet は 12×12・メモ20枚でも数KBなので、実用上の上限は考えなくてよい。

## 11. 共有URL

### 11.1 置き場所

**クエリパラメータではなくハッシュフラグメント**に入れる: `https://example.com/#s=<payload>`

理由は2つ。フラグメントはサーバーに送信されないので盤面が外に出ない。そしてクエリと違い長さ制限が実質ない。

### 11.2 エンコード

1. 以下をビットパックして `Uint8Array` にする
   - バージョン 1バイト
   - N 4ビット、種別（regular/daily/unknown）2ビット
   - `regions`: セルあたり 4ビット × N²
   - `imported`: セルあたり 2ビット × N²
   - メモ数 5ビット
   - メモごと: `showImported` 1ビット、`user` 2ビット × N²
   - 盤面名・メモセット名: UTF-8 長さ+本体
2. `CompressionStream('deflate-raw')` が使えれば圧縮（使えなければそのまま）
3. base64url（`+/=` を `-_` と除去に置換）

11×11・メモ5枚で圧縮前 400バイト程度、base64 で 550字前後。LINE や iMessage で問題なく貼れる長さに収まる。

### 11.3 共有ページの挙動

- 開いた時点で**そのまま編集できる**。閲覧専用モードは作らない
- 編集内容は URL には反映しない（開いたあとは手元の一時状態）
- 画面上に「リセット」ボタン。押すとラベルが **本当に？** に変わり、もう一度押すと今見ているメモだけを URL の初期状態に戻す。他のメモには触らない。3秒触らなければ元のラベルに戻る
- 「保存」ボタンもあり、押すと自分の IndexedDB に MemoSet として取り込める（盤面名・メモセット名はURLの値をプリフィル）
- 共有元と共有先で `Board.id` は一致するので、同じレベルの共有を受け取ると自分の盤面グループに自然に合流する

## 12. テーマ

Meowdoku 本体の見た目に寄せる。クリーム地＋白い角丸カード＋茶色の文字＋丸ゴシック。

```css
:root {
  --bg:        #F6EFE7;
  --card:      #FFFFFF;
  --ink:       #6E4B3A;
  --ink-weak:  #A98E7E;
  --line:      #EADFD3;
  --accent:    #F0A868;   /* 猫セルのハイライト */
  --mark:      #FFFFFF;   /* バツのストローク */
  --radius-card: 22px;
  --radius-cell: 12%;     /* セル辺長に対する比率 */
  --shadow: 0 2px 8px rgba(110,75,58,.12);
}
```

- 書体: `"Hiragino Maru Gothic ProN", "Zen Maru Gothic", system-ui, sans-serif`。太さは semibold 中心
- ボタンは白い円＋やわらかい影。アイコンのみ、ラベルは付けない（リセットの「本当に？」だけ例外）
- セルは角丸の正方形、間隔はセル辺長の 4%
- バツは白の2本線、線幅はセル辺長の 11%、端は丸く、セル辺長の 26% だけ内側に余白
- 猫は絵文字やイラストではなく、**塗りつぶしの丸＋2つの三角の耳**で記号化する。ゲームの猫アートは持ち込まない（著作物なので）。ハイライト背景 `--accent` と組み合わせて識別させる
- 領域色はスクショから読み取ったパレットをそのまま使う。固定の色表は持たない
- ダークモードは作らない（ゲーム本体が明色固定のため）

### 文言

- 画面上の文字は「保存」「リセット」「本当に？」「追加」程度に留める
- 空状態・エラー・ヒントの説明文は書かない。読み取り失敗時は補正画面をそのまま出す

## 13. 批判的レビューと追加提案

### 入れるべきだと思うもの

**自動除外トグル（強く推奨）** 猫を1匹置いたとき、同じ行・列・色・8近傍を自動でバツで埋める。手で埋めるとドラッグ十数回、しかも塗り漏らしが致命的なミスになる。このツールの価値の半分はここにある。既定OFF、設定パネル（§7.4）のトグル。自動で置いたバツは Undo 1回でまとめて消える。

**ルール違反の静かな表示（推奨）** 猫が行・列・色で重複したとき、または隣接したときに、該当する猫のセルの縁だけ細く赤くする。文章は出さない。仮定を進めた末の矛盾に気づくのが目的で、答えを教える機能ではない。既定OFF、設定パネル（§7.4）のトグル。

**Undo / Redo（必須）** 仕様に入れた（§7.3）。ドラッグで盤面を壊す事故が必ず起きる。

**盤面の手動作成（必須）** 読み取りは必ず失敗する日が来る。空の N×N から領域を手塗りできる経路を残しておく。補正UI（§6）をそのまま流用できる。

**クリップボード貼り付け（推奨）** iOS ならスクショ → コピー → ブラウザに戻って貼り付け、が最短。ファイルピッカーより速い。

### やめたほうがいいと思うこと

**猫セルの背景色から領域を推定すること** スクショ1では猫のセルがオレンジと金色になっており、領域色が上書きされている。色で追うと必ず壊れる。§5.4 の解決順で処理し、決まらなければ人に聞く。

**OCR の結果を無条件で名前に入れること** スクショ2はヘッダが通知バナーで潰れている。この状態で数字を拾うと、たとえば `62` を `2` と読んで別の盤面として保存される。信頼度が低ければ空欄にする方が被害が小さい。

**ダブルタップの判定を待つこと** §7.1 に書いたとおり。300ms 待つ実装だとバツ1つ置くたびに遅延が乗り、メモツールとして成立しない。

### 検討の余地があるもの

- **PWA 化**: ゲームとブラウザを往復するので、ホーム画面から一発で開けると体感が変わる。Service Worker はアプリシェルのキャッシュだけ
- **色の可読性**: Meowdoku のパレットには近い緑が複数ある（スクショ1の黄緑と濃緑）。領域の境界に細い白線を引くと、メモとしての可読性が本体より上がる。設定パネル（§7.4）のトグルとして採用、既定OFF
- **行・列ハイライト**: セルを長押ししている間だけ、その行と列を薄く光らせる。設定パネル（§7.4）のトグルとして採用、既定OFF
- **スクショ複数枚の一括インポート**: 同じ盤面の進行違いを並べて比較したくなる可能性がある。ただし最初のバージョンでは不要
- **OGP 画像**: 共有URLに盤面のプレビューが出ると気持ちいいが、静的ホスティングでは動的 OGP が作れない。やるならビルド時固定の1枚で妥協する

## 14. 決定事項と実装順

- レイヤーは `user` 1枚。表示ON/OFFは描画とロックだけを変える。既定はOFF（§8）
- 共有ページのリセットは**今見ているメモだけ**（§11.3）
- 自動除外・ルール違反の表示・行列ハイライト・領域の境界線は、設定パネルの**既定OFF**トグル（§7.4）
- スクショ1枚目=デイリー、2枚目=レギュラー

未決事項は現時点でなし。

### 実装順の提案

1. 盤面モデル・描画・タップ/ドラッグ/Undo（スクショなし、手動で N と領域を指定）
2. 下部スクラバーと複数メモ
3. インポートレイヤーのON/OFF
4. 画像解析（グリッド検出 → 領域色 → 猫/バツ → レベル名の順、各段階でテスト画像を通す）
5. 補正UI
6. IndexedDB 保存と一覧
7. 共有URL
8. 設定パネル（自動除外・違反表示・行列ハイライト・境界線）

1〜3 だけでもツールとして使える状態になるので、そこを先に動かして触りながら 4 以降を詰めるのが早い。
